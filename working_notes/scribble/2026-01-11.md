### Thoughts

1) **직관적인 정의**

> 알고리즘이 입력 전체를 한 번에 볼 수 없고, 대신 특정 위치의 값만 물어볼 수 있을 때, 그 "물어보는 행위" 한 번을 말한다.

다시 말해서, 계산 시간, 메모리 등에 대한 이야기보다는 완전히 이론적인 틀. **정보 접근 능력**을 의미.

2) **Boolean query란?**

입력 값이 0 또는 1(혹은 -1, 1)

non-Boolean query와 구분해서 이해한다면:

**Boolean query:**
- 질문: "이 입력의 값은 0이야? 1이야?"
- 반환값: 비트 1개

**non-Boolean query:**
- 질문: "이 함수 전체에 대한 어떤 연산을 한 번에 해줘"
- 반환값: 실수, 위상, 벡터 성분 등

예를 들면:

Period Finding에서 사용하는 query는

```
|x, y⟩ ↦ |x, y ⊕ f(x)⟩
```

처럼 함수값 전체 구조를 이용함

→ 이건 사실상 Boolean query보다 훨씬 강력한 접근 권한입니다.

3) **양자 query?**

> 입력의 특정 위치를 묻는데, 그 위치를 중첩된 상태로 동시에 묻는 것.

즉, *전체 입력*을 한 번에 다 읽는 건 아니지만, *간섭*을 확인해서 전역적 구조를 추출 가능.

Q: 이해가 안 되는 데. 양자 구조에서 어떻게 peek 하듯이 정보를 열람함?
A: measurement의 개념이 아님. 
```
(1) 상태 준비
(2) 입력과 결합하는 unitary 연산들 (← 여기가 query)
(3) 내부 간섭/연산
(4) 마지막에 단 한 번 측정
```
양자 연산이 위의 구조를 따른다고 할 때, (2)가 query에 해당함.
다만 phase를 넣을 뿐인.. > 다만 입력을 상태에 결합할 뿐인.

Q: 그럼 측정보다 임베딩과 관련된 개념? 그리고 오로지 phase만 바꿀 수 있음?
A: **양자 query는 "입력 정보를 양자 상태에 임베딩하는 공식적인 유일한 통로"**이고,
표준 query에서는 오직 phase(위상)만 바뀝니다
(다만, 다른 형태로 동등하게 표현할 수는 있습니다).

---

**표준 query 연산:**
```
O_z: |i⟩ ↦ z_i|i⟩, z_i ∈ {+1, -1}
```

다시 생각해보니까, 구조가 상태를 유지하거나 뒤집거나 둘 중 하나네. 일종의 bit-flip이라고 봐도 될지 모르겠음. 어쨌든 측정 상으로의 의미는 완전히 동일하지만.
> 그럼 non-boolean query 자체가 이 부분이겠네. 더 이상 비트 플립으로만 제한되지 않는다는 거겠지.  
---

4) **진짜 의미는 "중첩 상태"에서만 나타납니다**

핵심은 이겁니다.

**중첩 상태:**
```
|ψ⟩ = α|i⟩ + β|j⟩
```

**query 이후:**
```
O_z|ψ⟩ = αz_i|i⟩ + βz_j|j⟩
```

이제 경우가 갈립니다:

- **z_i = z_j**: 전체 위상만 바뀜 (물리적으로 무의미)
- **z_i ≠ z_j**: 상대적 위상(relative phase) 변화

→ 의미 있는 변화는 오직 두 번째 경우

### Thoughts
1) **논문에서 문제로 삼는 포인트**

non-boolean query를 허용한다면: 
> “the separation becomes easy”
즉, 문제가 조금만 이상해도, 양자가 너무 쉽게 이기게 됨.  
“양자에게는 전체 파일을 주고 고전에게는 한 줄씩 읽게 하는 것”이나 다름 없기 때문임.

**Q:** 그게 공정하지 않다는 걸 어떻게 엄밀하게 말할 수 있음? 내게 있어서 불리안-쿼리란 "비트를 독립된 비트로만 다루고, 임베딩 과정에서 비트끼리의 상호 작용은 고려하지 않는다"는.. 대략적인 공정한 느낌은 알겠지만 여전히 non-boolean query를 한 번의 연산으로 가하는 건 양자 도메인 자체의 이점 아님?(반칙이라기 보다는, 본질적인.)
**A:** 시뮬레이션 가능성 (polynomial simulation criterion)

더 엄밀한 기준은 이겁니다:
양자에게 허용된 단일 query 연산이
고전 알고리즘에서도
다항 개수의 Boolean query로 시뮬레이션 가능한가?
가능하다 → 같은 접근 모델
불가능하다 → 정보 접근이 다름
이게 “반칙인지 아닌지”를 가르는 표준적인 수학적 기준입니다.
→ non-Boolean query는 고전적 시뮬레이션이 불가능

2) **oracle과 gate의 역할 분리**

oracle은 외부 정보 접근  
gate는 내부 계산

즉, 만약 non-boolean query가 `Boolean query + poly(n) gates`로 항상 분해 가능하다면, 그건 같은 oracle 모델입니다. 이 기준 하나로 정리됩니다.

**비-Boolean oracle이 Boolean oracle을 다항 번 호출해서 시뮬레이션 가능한가?**

- ✔️ 가능 → 같은 정보 접근 모델
- ❌ 불가능 → 입력 모델이 바뀐 것

대부분의 non-Boolean query는:
- 실수 정밀도
- 전역 함수 구조
- Fourier 계수

를 한 번에 제공하므로, 다항 Boolean query로 복원 불가능합니다.

oracle 단계에서 이미 비트 간 결합을 허용한다 → 즉, 오라클이 사실상 계산을 다 해준다.

**Q:** 오라클과 게이트가 가지는 철학적인 역할 분리가, non-boolean query에서 무너짐?

**A:** 수학적인 뭔가가 무너지는 게 아니라, 철학적 역할이 무너진다고 볼 수 있음.

**Metadata:**

### Trigger
- Read: []()

### Thoughts

1) **최대 분리의 의미**

이 문제에서 만들어낸 분리가, 사실상 고전-양자의 최대 분리임. (이보다 더 나을 수 없음)  

예컨대 앞서서:
```
Buhrman et al. (2002):
Boolean 입력에 대해

양자: O(1)
고전: Ω(N)
이런 “완전한” 분리가 가능한가?
```
이런 의문이 있었는데, 논문에서 보기엔 사실상 이런 분리가 불가능.

---

2) **왜 불가능한가?**

양자 알고리즘으로 최소 t번의 쿼리로 어떤 문제가 풀린다고 하자. 그럼 적어도 고전 랜덤 알고리즘으로 `O(N^(1-1/(2t)))`로 풀리기 때문임. 그리고 이건 우리가 구한 것과 비슷함.

> 모든 t-query 양자 알고리즘의 acceptance probability는 입력 비트들에 대한 차수 ≤ 2t 인 다항식으로 표현된다.

우리가 오라클 단위에서 연산을 제약하면, 양자 알고리즘도 결국 저차 상호작용만 만들어낼 수 있음.  
---
3) **고전적으로 근사 가능한 이유**

전체 큐비트의 값을 다 볼 필요가 없음. 다 보지 않아도 accept, reject는 결정 가능하기 때문에. 나머지 큐비트들은 간섭을 만들어내기 위한 내부 구조에 더 가까움.

→ 이게 바로 고전적으로 근사 가능해지는 이유.

**Q:** 연산을 아무리 한다고 해도, 고전이든 양자든 실제 보는 건 그 계산이 압축된 작은 비트 스트링 값이기 때문에 따라잡을 수 있다는 거야? 그럼 그게 양자가 보는 쿼리가 늘어나는 것과 무슨 상관?
**A:** 하지만 결정적인 건 ‘출력의 크기’가 아니라,
그 출력이 입력에 대해 얼마나 복잡하게 의존할 수 있느냐이고,
그 복잡도를 정확히 제한하는 게 query 수입니다.
출력이 작아도 입력과의 의존성이 고차(high-degree)이면 고전은 못 따라옵니다.

---

4) **Theorem 1.3의 핵심**

Theorem 1.3에서는 단순히 가 아니라, 훨씬 강한 말을 합니다.

“출력이 작다”

**출력 확률 `p(x)`가 입력 비트들에 대한 차수 ≤ 2t 다항식이다.**

이 말은 곧:

- `p(x)`는 최대 2t개 비트의 상호작용만 포함
- 즉, 전체 N비트가 한꺼번에 얽힌 항은 존재할 수 없음

**Note:** 즉, 양자라고 해도 출력과 입력의 상호작용이 무한 고차 항으로 올라가지 않는다는 말임.

**Metadata:**
- `@project`: qhydra
- `@topic`: 계산 복잡도와 알고리즘 비용 계산

### Trigger
- Read: []()
- Context: 애초에 어떤 알고리즘에 대해서 비용 계산을 어떻게 하는 거지?

### Thoughts

1) **SAT (Boolean Satisfiability Problem)**

예를 들어서 SAT를 보고, 이 알고리즘의 계산 복잡도를 어떻게 계산한다는 걸까?

**SAT 정의:**
> 어떤 불리언 변수들에 참/거짓 값을 잘 넣으면, 주어진 논리식 전체를 참으로 만들 수 있을까?  
> 식을 참으로 만드는 조합을 찾거나, 그런 조합이 없다는 것을 증명하는 것.

2) **불리언 논리 기본 연산**

**우선 불리언 논리부터 살펴보자:**

- `¬` (NOT, 부정): e.g. x = True → ¬x = False
  - 알고리즘적으로는 상수 시간 연산
- `∨` (OR, 논리합): 하나라도 True면 True
- `∧` (AND, 논리곱): 모두 참이어야 참

**예시:**
```
(x₁ ∨ ¬x₂ ∨ x₃) ∧ (¬x₁ ∨ x₄)
```

이거 자체가 그냥 문제 인스턴스인 셈.

3) **가장 간단한 접근: 완전 탐색**

가장 간단하게 생각하면, 모든 가능한 수를 전부 탐색해본다고 하자. 그럼 `2^n`이 총 경우의 수니까, 그걸 넣어보면 되지.

```
T(n) = 2^n · O(절 개수)
```

하지만 좀 더 나은 방법을 시도해보자.

4) **개선된 접근: 조기 종료**

> 전부 다 넣어보지 말고, 중간에 포기할 수 있을까?

`(x₁ ∨ ¬x₂ ∨ x₃) ∧ (¬x₁ ∨ x₄)` → 여기서 AND로 들어가 있는데, 앞이 거짓이면 굳이 뒤를 해 볼 필요 없음. 그 경우의 수를 모두 빼버려도 됨.

이 단계에서 이미 SAT 알고리즘의 기본 구성요소가 다 나옵니다:

- **① 부분 할당 (partial assignment)**: 모든 변수를 한 번에 정하지 않음, 일부만 정하고 상태를 본다
- **② 즉시 실패 감지 (early conflict detection)**: 어떤 절이 False가 되는 순간 → 그 분기 폐기
- **③ 단위 전파 (unit propagation)**: 절에 리터럴 하나만 남으면 → 그 변수는 강제됨

이 세 개를 합친 것이 DPLL 알고리즘의 뼈대입니다.

**Q:** 어디서 시작할지는 그다지 중요한 게 아님? 예를 들어서 x₃부터 시작한다던가. 1절부터 시작한다던가. 분기가 실패하면 1절을 시도하다가 어느 순간에 2절로 넘어간다던가 그런 시도를 할 수 있을까..


## [22:34] twisted sum
### Thoughts 
가장 간단한 예시를 들고 진리표를 그려보자!  

> - 입력 공간: $({0,1}^2 = {00, 01, 10, 11})$
> - twisted sum (k=2):
> $\Phi_{f,g}\frac{1}{2^{3}}\sum_{x,y \in {0,1}^2}  f(x),(-1)^{x\cdot y},g(y)]$  
> 이때
> $x \cdot y = x_1 y_1 + x_2 y_2 \pmod 2$

1) 둘 다 평평한 함수인 경우
즉 f = 1, g = 1  

**이제 핵심**: "$(-1)^{x\cdot y}$가 언제 −1이 되는가?"

|x|y|겹친 1의 위치|개수|x·y|위상|
|---|---|---|---|---|---|
|00|00|없음|0|0|+1|
|01|01|2번째|1|1|−1|
|01|10|없음|0|0|+1|
|11|11|1,2번째|2|0|+1|
|11|01|2번째|1|1|−1|

👉 보시다시피  
**“0이 있느냐”가 아니라 “겹친 1의 개수의 홀짝”** 입니다.

그리고 이 구조를 다시 $\Phi_{f,g}$로 보면, 값은 0.
즉, 서로 무관한 함수 -> 위상들이 정렬(?)되지 않음...  
2) g가 f의 푸리에 구조를 따르는 경우

### f 정의


$f(x) =  
\begin{cases}  
+1 & x = 00, 11 \    
-1 & x = 01, 10     
\end{cases}$

(패리티 함수)

---

### g 정의 (f의 Hadamard 이미지라고 생각)
  
$g(y) =  
\begin{cases}  
+1 & y = 00 \  
-1 & y = 11 \  
+1 & \text{otherwise}  
\end{cases}$

(완전히 정확한 Fourier transform은 아니지만, 구조를 공유)
---

**Q:** 어떻게 하다마르 게이트가 이산 푸리에 변환과 대응되지?

**A:**

하다마르 게이트 행렬:

```
H = (1/√2) [1  1]
           [1 -1]
```

작용을 보면:

```
H|0⟩ = (|0⟩ + |1⟩)/√2
H|1⟩ = (|0⟩ - |1⟩)/√2
```

이건 단순한 회전이 아니라, **"값의 기저 → 부호(위상) 기저"로 바꾸는 연산**입니다.

> **“값의 기저 → 부호(위상) 기저”로 바꾸는 연산**
